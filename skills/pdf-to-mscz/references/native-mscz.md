# 原生 MSCX／MSCZ 修订与验证

仅在复用已有 MuseScore 文件、直接修订 MSCX、或排查保存后变化时读取。这里是已验证流程的注意事项，不是完整的 MuseScore 格式规范；先检查当前版本的实际文件，不照搬某首歌的 ID 或补丁。

## 主谱与样式一起保留

- MSCZ 是 ZIP 容器；用 `META-INF/container.xml` 指定的主谱，检查 ZIP 完整性。分谱存在时不能取遇到的第一个 `.mscx`。
- 样式可能另存在 `score_style.mss`。只抽取主 MSCX 再打开可能丢失纸张尺寸、谱表间距、隐藏空谱表等，造成页数暴增。保留并加载对应样式，或按当前文件结构把正确的 `Style` 合入 `<Score>`；经 MuseScore 保存后再确认样式与渲染，不能只相信 XML 中已写入。
- 用独立中间目录保存每个拟导入的原生稿及其配套文件，避免不同试稿混用样式或其他配套材料。MuseScore 保存未压缩稿时可能产生旁置的样式、缩略图和容器文件；分享最终曲谱用确认过的 MSCZ。
- 保留源文件及上一版；新修订另存。不要覆盖正在另一个窗口打开且尚未确认保存状态的文件。

## 时间与记谱的独立语义

- 用有理数记录每个小节、voice 的独立游标，并解释 `location`、附点、实际小节长度、tuplets 和 grace；仅遍历 XML 顺序不能得到可靠起拍。原生位置分数一般以全音符为单位，与四分音符拍数转换时明确单位。
- 非主 voice 的结尾可能只有部分时值，这是合法写法之一。先对照原谱，不能为“每个 voice 满拍”机械补休止或改音符。
- 同一总时值可能有不同的 `durationType` 和显示形态；整小节休止、普通休止、装饰音符尾及小音头需独立比较。音符 `small` 与 grace 不是同一个概念。
- 音高比较保留原谱拼写、记谱八度及临时变音，并考虑声部的谱号、八度移位与移调；MIDI 值只能作为辅助。

## 双端连线与零时值标记

- 部分版本的原生文件用 `Spanner` 起点／终点和相对位置表示连线。修改前理解当前版本的编码；不要将全部连线统一处理为只含两个拍点的简化结构。
- 对 tie 比较起止的具体音符，对 slur 比较起止和弦／voice；检查前向和反向端点互相闭合，排除悬空、重复或多余端点。和弦中不同音符的 tie、跨 voice 的 tie 都要分别核验。
- grace 可能与主音共享时间坐标，仍需单独的 grace 索引／端点定位。只匹配“同小节同拍”会把倚音连线接错对象；保存回读及渲染均须确认。
- 跨小节相对位置在保存时可能被重写。将起止位置换成同一时间基准后比较，不要把等价的序列化变化当成乐谱错误；也不能只靠总条数放行。
- 力度、渐强渐弱、文字等不应推进音符游标。需要插入非起音位置的标记时，可使用当前格式支持的相对定位；修订后确认后续音符起拍完全未变，再验证标记的准确拍点和所属谱表。

## 最小改动与最终验收

补丁以固定基线为输入，对已定位旧值做前置断言，只改负责字段。保持音乐事件、歌词、连线、样式等层之间的隔离；合并后重新核对所有层，不能只检查刚刚改的字段。

必须用 MuseScore 保存为实际 MSCZ，关闭并重开这个文件，再做内容回读和 PDF 渲染。`scripts/inspect_score.py` 仅提供结构统计，未实现完整声部时序或上述逐项验证；需要编写针对当前原谱的比较器或人工对照记录。不要把本曲专用提取器包装成适用于任意乐谱的 OMR。
