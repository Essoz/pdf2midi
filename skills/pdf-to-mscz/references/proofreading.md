# 原谱精校与保存后验证

“精校”指对完整授权范围进行独立的源谱核对，不是校验文件格式。以下方法适用于不同歌曲；不要把某首歌的页数、调号、声部数量、字体坐标或小节编号硬编码成通用规则。

这是转换请求的默认流程。只有用户明确要求初稿、基础转换或不精校，才减少核对深度；指定局部曲目／页段时，对该授权范围完成精校，不擅自扩展到其余部分。

## 覆盖记录与并行合并

在任务目录保留原 PDF、原始 OMR、固定的校对基线、修订清单、实际保存后的核对报告和最终渲染。记录原件与最终文件的路径及指纹，避免拿旧渲染或另一版 PDF 验收。

按声部／页段记录覆盖状态：源页与系统、小节区间、已核对音高节奏、歌词、连线与演奏记号、未决项、最终文件复验及视觉检查。没有歌词或没有表情记号，也要确认其在源谱中确实不存在。用这张记录识别遗漏，不能只抽查首尾或高风险小节就称全谱精校。

有多个执行者时，各自从原谱独立核对分配范围，共用一个未改动基线。每个修正记录定位、原值、新值和原谱证据，修改前断言目标仍是所检查的旧值；只修改负责的字段。由一个执行者合并，检查冲突和重复应用，最后对合并稿重新验证所有层。独立复核可提高可信度，但不要把多人赞同代替源谱证据。

## 来源与对照索引

先建立页 → 系统 → 声部 → 小节的对应关系，再核对具体符号。用每页系统起始小节、特殊节奏、休止区段、调号变化和终止处做锚点，识别错页、漏页、合并小节及错位声部。

用户限定页段时，可读取必要的相邻上下文以确认继承的谱号、调拍号、跨页连线和反复关系，但输出与修改仍限授权范围。明确记录节选边界上未结束的音乐结构；不要为了让节选独立播放而默默补写终止、删除连线或改写跳转。

进入精校后，矢量 PDF 的文字、字形位置和路径可用于独立核对 OMR 初稿或用户提供的乐谱。先用清晰局部核实映射，冲突处放大原谱判读，并记录声部、小节与拍位。不能用这些数据生成识别初稿，再让同一份数据给初稿验收。扫描图没有可直接复用的矢量索引。

需要逐项比对时，以独立观察的原谱建立事件索引。例如：

```json
{
  "page": 2,
  "system": 1,
  "part": "Alto 1",
  "staff": 1,
  "measure_index": 17,
  "printed_measure": "16",
  "voice": "1",
  "onset_quarters": "3/2",
  "duration_quarters": "1/2",
  "pitch": {"step": "F", "alter": "1", "octave": 4},
  "rest": false,
  "visible": true,
  "confidence": "verified"
}
```

这是建议的数据形状，不是附带脚本的输入要求。使用有理数记录时值，区分文件顺序与印刷小节号，允许弱起、重复编号和非整数临时记号。对照记录还应保留实际记谱类型、附点、倚音类型、连音组与显示大小；和弦按成员记录拼写。必要时附原谱局部坐标或裁图。来源未确认的事件标明不确定性，不通过脚本投票把它变成事实。

## 核对顺序

### 1. 全曲结构

- 页／系统是否完整；声部与多谱表 part 的对应、顺序、名称是否正确。
- 小节数量、弱起、拍号变化、不完整小节、自由节奏、反复、房子、D.S./D.C. 等实际演奏结构。
- 谱号与八度移位、调号、移调乐器；区分记谱音高和实音。
- 隐藏的空谱表不等于缺失声部；结合相邻系统和全曲结构确认其静默区间，不能凭版面空白猜造可见休止符。每个系统重复出现的调号不等于新的临时变音。
- 结尾空小节、整小节休止与终止线可能属于原谱，不因“看起来没用”删除。

### 2. 音高和节奏

- 核对符头位置、升降还原与本小节生效范围、附点、符尾／连梁、休止、和弦、连音组、倚音、跨谱表及多 voice。
- 用音名＋alter＋octave 保留拼写；仅 MIDI 数值相同不足以确认同音异名拼写正确。
- 计算每个声部的起拍与时值。MusicXML 的 `backup`/`forward` 移动游标，`chord` 不推进新起拍；`divisions` 可能改变。不可把所有 note duration 简单相加。
- MSCX 的时值还可能受附点、tuplets、`location`、整小节休止、grace 与嵌套结构影响。没有实现这些语义的脚本应输出“不支持／待查”，不能宣称全拍核验通过。
- 同一 voice、同起拍的多个符头可属于一个和弦；按实际结构确认其成员，音符数、和弦数与起音数不能互换。
- 同音高且同起拍的音符可能属于不同 voice，不能因此合并或去重。核对独立符干、连梁和声部分配，保留其单独时值。
- **显示形态与演奏时值分别检查**：倚音不推进正常拍点，但其符尾、斜杠和连线仍须正确；小音头可能是正常占拍音符，不能直接改为 grace。弱起中的一拍休止，显示成整小节休止也可能时值总数不变，仍须按原谱修正。
- 原谱小节不满拍时，先确认是否弱起、自由节奏或真实缺写。仅在确定需补齐机器时值时加入隐藏休止，并明确记录位置与原因；不要将这种修复用于所有不满拍小节。

### 3. 歌词与延长线

- 核对实际文字、声部／voice、verse、小节、拍位、音符对位、连字符和跨系统延长线。
- 原谱拼音不擅自替换汉字；原谱没写的主唱歌词不按听歌补全。保留 `dm`、`dom`、`doo` 等实际音节。
- 原谱中的疑似错字、重复字或不常用写法照录并在说明中标出；除非用户要求订正，不依据记忆、网上歌词或其他版本默默替换。
- PDF 中文字体可能采用无意义的 CID 编码。先用清晰字形建立并目视核实文字映射，再把歌词锚定到独立确认的音乐事件；不要继承可能已错位的 OMR 对位。多个 voice 共用同一个印刷音头和一份歌词时，先确认视觉归属，避免重复文字。
- 区分含文字的 lyric 与仅含 `<extend>` 的结构节点。原始 lyric 元素数不同，不一定丢字；非空文字应按对位逐项比较。
- `(cut!)`、`FREESTYLE` 等按语义放在演唱指示中，不机械作为歌词音节。移动这些指示后，重新检查其前方 melisma 的终点。
- 某些导入把延长线的 stop 对应到末音结束而非所需起点，造成多出半拍等偏差。按源谱逐条判定，不能对所有延长线统一减一个固定值。
- 直接修订保存文件时先备份，只改已定位字段。MSCX 中 `ticks_f` 使用全音符分数，不能把四分音符拍数原样填入；旧式 `ticks` 需根据文件版本／division 解释。改后重新打开、回读并检查实际渲染。

### 4. 连线、表情与文字

- tie 与 slur 分别处理；不仅数条数，还核对声部、起止小节、拍位及音高。跨系统曲线可能分成多段，同一逻辑连线不重复计数。
- 对和弦逐音核对延音线，对旋律／声部核对连奏线；同音不自动等于 tie。分开的上下 voice 可能保留相同的连奏范围，跨 voice 的延音也需根据原谱逐条确认。倚音到主音的短连线不能错接到后一个普通音。
- 核对力度、渐强渐弱、速度与变化、延长记号、呼吸／断音／重音、演唱文字、反复结构和最终小节线。
- 力度和渐强渐弱按准确拍点定位，不机械吸附到最近的音头；标记可以落在本声部没有起音的位置，可参照同系统其他声部的节奏列。先确认所属谱表再看最近距离，钢琴两谱表之间的力度不能错配给相邻人声。单独核对每条渐强渐弱的起点、终点及方向。
- 对断音、保持音、重音、延长号、琶音等核对类型、作用音符／和弦、方向和可见性。曲线路径与复合字形可能有多段，按逻辑记号去重；不能把提取路径数当成实际记号数。确认后才删除 OMR 产生的多余滑音线或其他伪记号。
- 速度除数值外，还核对节拍单位：四分音符与八分音符的同一数字代表不同速度。分段双小节线和终止线需检查所有相关谱表，不能只改最高声部。
- 不补写原谱没有的 BPM、力度或唱法。默认播放速度不是原编曲的速度标记。
- 标题、副标题、编曲与作曲署名要区分。MuseScore 可能使用富文本框显示 `Arr.` 署名；同时检查可见排版与元数据，别因字段名称叫 composer 就改变署名身份。

## 保存后的两层验证

**内容回读：** 从实际交付的 MSCZ 按容器清单读取主谱，再与已经独立核对的源索引／MusicXML 逐项比较。比较缺失、额外和不同的事件，不能仅检查总数；歌词比对文字与对位，记号比对类型与作用位置，连线比对两端。MuseScore 可能重写内部 ID 或相对位置，按音乐语义归一化后比较，不能因此放宽真正的拍点差异。隐藏的编辑性补入单独列出。MusicXML→MSCZ 零差分只证明转换保持了输入，不证明输入忠于 PDF。

**视觉检查：** 使用该确切 MSCZ 在 MuseScore 导出的 PDF，逐页检查谱表、换行、歌词、延长线、连线、提示文字和边缘。对疑似缺失或碰撞放大局部检查；缩略图误读不应引起改谱。必要时检查渲染中的文字位置作为辅助，不能替代视觉观察。

最终页数可能因重排改变，仍须检查全部输出页；尤其放大所有已修正的特殊记谱，例如低加线音、倚音符尾、小音头、重叠 voice、多层延音与跨系统连线。语义正确、无歧义的分页或指示上下位置变化可记为非阻断排版差异，不必为了凑原页数压缩到不可读。

若新增输出或修复改变了音乐字段，重跑相应内容比对；如果仅调整了排版，也需重新渲染受影响页。报告分别记录已通过的内容核验、视觉核验和仍未覆盖部分。

## 交付措辞

- 只有结构／打开检查：说“转换版，已做基础校验，未逐音精校”。
- 只校对部分页或声部：说出具体覆盖范围。
- 全部源谱内容与最终渲染均核对后，才称“全谱精校版”。
- 源谱不清、自动识别无法覆盖的复杂记谱、实际保存或渲染未完成时，列出具体未解决项，不以文件名中的“精校”代替证据。
